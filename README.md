# Daily Business English Mailer

매일 아침, **내 Gmail 계정에서 회사 메일로** 비즈니스 영어 학습 메일을 자동 발송하는 시스템입니다.
Google Apps Script로 동작하므로 별도 서버·비용 없이 Google 계정 안에서 매일 돌아갑니다.

## 무엇이 오는가

하루 한 통, 3개 카테고리 × (문장 2개 + 단어 2개) = **문장 6개 + 단어 6개** (약 5분 분량)

| 카테고리 | 내용 | 활용 상황 |
| --- | --- | --- |
| 1. 영어교육이론 | ELT 이론 용어와 설명 문장 | 교사 트레이닝, 총판 대상 제품 설명, 교재 개발 회의 |
| 2. 비즈니스 협상 표현 | 계약·가격·결제조건·채권·라이선스 | 총판 협상, 전시회 상담, 클레임 대응 |
| 3. 미팅 표현 | 회의 진행·보고·이견 조율 | 화상회의, QBR, 팀 회의, 연수 진행 |

각 문장에는 한국어 해석과 **"언제 쓰는 표현인지"** 힌트가 붙고, 카테고리마다 **근거 문헌과 자료 링크**가 따라붙습니다.
메일 하단에는 **어제 배운 단어 6개 복습** 섹션이 들어갑니다.

- 콘텐츠: 카테고리별 40일치(총 문장 240개 / 단어 240개). 주말 제외 발송 기준 약 2개월.
- 40일이 끝나면 자동으로 2회독으로 순환합니다(제목에 `2회독` 표기). 새 콘텐츠는 아래 "콘텐츠 추가하기" 참고.

### 복습 퀴즈 (4일째마다)

학습 3일치를 마친 **그다음 날** 저녁 7시에, 그 3일치에서 **랜덤 10문항**을 뽑아 따로 보냅니다.
(Day 4에 Day 1~3, Day 7에 Day 4~6 …) 하루 묵힌 뒤 인출하는 편이 기억에 더 오래 남습니다.

메일 본문에는 답을 쓸 수 없으므로, 같은 퀴즈를 **답 칸이 있는 구글 문서**로 만들어 링크를 걸고
**Word(.docx) 파일로도 첨부**합니다. 문서에는 문항마다 입력 칸이 있고, 정답은 페이지를 나눠 뒤에 둡니다.
문서는 내 드라이브의 `Daily Business English` 폴더에 쌓여 학습 기록이 됩니다.

| 유형 | 문항 수 | 내용 |
| --- | --- | --- |
| 단어 영작 | 4 | 한국어 뜻 + 영문 정의를 보고 단어 쓰기 (첫 글자 힌트 제공) |
| 빈칸 채우기 | 3 | 예문에서 빠진 단어 채우기 |
| 문장 영작 | 3 | 한국어 문장을 영어로 말해 보기 (사용 상황 힌트) |

메일과 문서 모두 맨 앞에 푸는 방법이, 문항마다 유형별 안내가 붙습니다.
정답은 맨 뒤에 모아 두어 먼저 풀어 본 뒤 확인할 수 있습니다.
주기·시각·문항 구성은 아래 설정값과 `Quiz.gs`의 `QUIZ_PLAN`에서 바꿀 수 있습니다.

> 회사 메일 계정은 개인 Gmail과 다른 계정이므로, 스크립트가 문서에 **편집자 권한을 자동으로 부여**합니다.
> 조직 정책으로 외부 공유가 막혀 있으면 링크 대신 첨부된 Word 파일을 쓰면 되고, 메일에도 그렇게 안내됩니다.

## 콘텐츠는 어디서 오는가

**문장과 예문은 이 저장소에서 직접 작성한 것**입니다. 특정 교재나 코퍼스에서 발췌하지 않았습니다.
선정 기준은 세 가지입니다.

1. **개념 선정** — 영어교육학에서 표준적으로 다루는 핵심 개념을 커리큘럼 순서로 배열
2. **문장 작성** — 그 개념을 실제 업무 상황(교사 트레이닝, 총판 제품 설명, 채택 심사, 계약 협상)에서
   말할 법한 문장으로 새로 작성
3. **어휘 선정** — 해당 개념의 표준 전문용어와 실무 관용 표현

즉 **개념은 학계·업계의 것이고, 문장은 창작**입니다. 그래서 메일에는 인용문이 아니라
**개념의 근거 문헌**을 표기합니다 (`Sources.gs`).

| 카테고리 | 출처 표기 | 비고 |
| --- | --- | --- |
| 영어교육이론 | 40/40 주제 | Krashen, Vygotsky, Cummins, Swain, Nation 등 대표 문헌 |
| 비즈니스 협상 | 6/40 주제 | Fisher & Ury, Raiffa, Incoterms, 베른협약 등 |
| 미팅 표현 | 2/40 주제 | Erin Meyer 등. 나머지는 실무 관행이라 출처 없음 |

**출처가 없는 주제는 비워 둡니다.** 실무 관행에 가까운 표현에 그럴듯한 문헌을 붙이는 것은
인용이 아니라 창작이기 때문입니다. `Sources.gs`의 원칙은 "확인되지 않은 문헌을 지어내지 않는다"입니다.

링크는 저자·서명으로 **Google Scholar 검색 주소를 생성**합니다. 특정 페이지 주소는 시간이 지나면
깨지지만 검색 링크는 사라지지 않고, 원문·인용 횟수·다른 판본을 한 번에 보여 줍니다.

출처를 추가하거나 고치려면 `Sources.gs`의 `SOURCES`에 학습 주제(`focus`)와 같은 이름의 키로
`{ author, work, year, note }` 를 넣으면 됩니다. 주제 이름이 틀리면 `tools/preview.js` 검증에서 걸러집니다.

## 설치 (10분, 1회만)

1. **스크립트 만들기** — [script.google.com](https://script.google.com) 접속 → `새 프로젝트` → 이름을 `Daily Business English`로 변경.
   - 반드시 **매일 메일을 보낼 계정(= 본인 Gmail)** 으로 로그인한 상태에서 만듭니다.
2. **코드 붙여넣기** — `apps-script/` 아래 7개 파일을 각각 같은 이름의 스크립트 파일로 만들어 붙여넣습니다.
   - `Code.gs` (기본 생성된 파일에 덮어쓰기)
   - `Quiz.gs` / `QuizDoc.gs` / `Sources.gs` / `Content_Theory.gs` / `Content_Negotiation.gs` / `Content_Meeting.gs`
     (좌측 `파일 +` → `스크립트`로 추가, 확장자 `.gs`는 자동)
   - 파일을 나누는 대신 전부 이어 붙여 `Code.gs` 하나에 넣어도 동일하게 동작합니다.
3. **시간대 확인** — 좌측 `프로젝트 설정` → 시간대가 `(GMT+09:00) 서울`인지 확인 (아니면 변경).
4. **수신 주소 지정** — `프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가`에서
   `RECIPIENT_EMAIL` = `본인@회사도메인` 을 넣고 저장합니다.
   - 편집기의 `실행` 버튼은 함수에 값을 넘기지 못하므로, 주소 설정은 스크립트 속성으로 합니다.
   - `setRecipient`·`setSendHour`·`goToDay`는 편집기에서 인자 없이 실행해도 안전하며, 현재 설정값만 로그로 보여 줍니다.
5. **권한 승인** — 첫 실행 시 Google 권한 화면이 뜹니다. 퀴즈 문서 기능을 쓰려면
   메일 발송 외에 **문서·드라이브 권한**도 필요하므로, 기존 프로젝트에 코드를 새로 붙여넣은 뒤에는
   권한 화면이 한 번 더 나옵니다. `고급` → `...(안전하지 않음)으로 이동` → `허용`.
   (본인이 만든 스크립트라 표시되는 정상 경고입니다. 메일 발송 권한만 사용합니다.)
6. **테스트 발송** — `sendTestEmail` 실행 → 회사 메일함 확인.
7. **자동 발송 켜기** — `setup` 실행. 매일 오전 7시(한국 시간) 트리거가 등록됩니다.

## 사용 중 조작

Apps Script 편집기에서 함수를 골라 `실행`하면 됩니다.

| 함수 | 기능 |
| --- | --- |
| `sendTestEmail()` | 학습 메일을 지금 한 통 발송 (진도는 올라가지 않음) |
| `sendTestQuiz()` | 복습 퀴즈를 지금 한 통 발송 (퀴즈 기록은 바뀌지 않음) |
| `showStatus()` | 현재 설정·자동 발송 상태·다음 발송 내용·퀴즈까지 남은 일수 확인 |
| `setSendHour(6)` | 발송 시각 변경 (0~23시). 편집기에서는 스크립트 속성 `SEND_HOUR`를 고친 뒤 인자 없이 실행 |
| `setRecipient('me@company.com')` | 수신 주소 변경. 편집기에서는 스크립트 속성 `RECIPIENT_EMAIL`을 직접 수정 |
| `goToDay(15)` | 특정 Day로 진도 이동. 편집기에서는 스크립트 속성 `LESSON_INDEX`를 수정 (Day 15 = `14`) |
| `resetProgress()` | Day 1부터 다시 시작 |
| `stopDailyLesson()` | 자동 발송 중단 (학습·퀴즈 트리거 모두 제거, 진도는 유지) |
| `setup()` | 중단 후 다시 켜기 |

### 설정값 (프로젝트 설정 → 스크립트 속성)

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `RECIPIENT_EMAIL` | (필수) | 회사 메일 주소 |
| `CC_EMAIL` | 빈값 | 참조 주소 (콤마로 여러 개) |
| `SEND_HOUR` | `7` | 발송 시각 (0~23) |
| `WEEKDAYS_ONLY` | `true` | `true`면 토·일 발송 안 함 |
| `SUBJECT_PREFIX` | `[Daily Biz English]` | 메일 제목 앞머리 (메일 필터·라벨 자동화에 사용) |
| `LESSON_INDEX` | `0` | 진도. 발송 성공 시 자동 +1 (Day 15로 옮기려면 `14`) |
| `QUIZ_ENABLED` | `true` | `false`로 두면 복습 퀴즈를 보내지 않음 |
| `QUIZ_EVERY` | `3` | 며칠치를 모아 퀴즈로 낼지 |
| `QUIZ_HOUR` | `19` | 퀴즈 발송 시각 (0~23) |
| `QUIZ_DOC` | `true` | 답을 쓸 수 있는 구글 문서 생성 및 링크 첨부 |
| `QUIZ_ATTACH_DOCX` | `true` | 같은 내용을 Word(.docx)로 첨부 |
| `QUIZ_LAST_INDEX` | `0` | 마지막 퀴즈 지점. 자동 관리 |

> 설정값을 바꾼 뒤에는 `setup`을 한 번 더 실행해야 트리거에 반영됩니다.

> 팁: Gmail에서 `제목에 [Daily Biz English] 포함` 필터를 만들어 라벨을 붙여 두면 학습 기록이 한곳에 쌓입니다.
> 발송 한도는 개인 Gmail 기준 하루 100통이라 여유가 충분합니다.

## 콘텐츠 추가하기

`apps-script/Content_*.gs`의 배열에 항목을 추가하면 됩니다. 형식은 다음과 같습니다.

```js
{
  focus: 'Comprehensible Input',            // 주제 (제목에 표시)
  sentences: [
    { en: '영어 문장.', ko: '한국어 해석.', use: '언제 쓰는지' },  // 2개
  ],
  words: [
    { term: 'collocation', pos: 'n.', ko: '연어',
      def: 'words that naturally occur together', ex: '예문' }     // 2개
  ]
}
```

세 파일의 길이가 서로 달라도 됩니다(각자 독립적으로 순환합니다). 다만 회독 표기는 가장 짧은 카테고리 기준입니다.

## 로컬 검증 / 미리보기

Node.js만 있으면 발송 전에 내용을 확인할 수 있습니다.

```bash
node tools/preview.js        # 형식 검증 + Day 1 메일 미리보기 → preview.html
node tools/preview.js 12     # Day 12 미리보기
```

`preview.html`(학습 메일)과 `preview-quiz.html`(복습 퀴즈) 두 개가 만들어집니다.
퀴즈 문서는 `buildQuizDocSpec_`이 만든 구조 배열을 검사하므로, 구글 API 없이도 내용을 확인할 수 있습니다.

검증 항목: 문장·단어 개수(각 2개), 필수 필드 누락, 주제 중복, 카테고리 내 단어 중복, 문장 종결부호,
그리고 모든 3일 구간에서 퀴즈가 10문항을 채우는지·정답이 중복되지 않는지·빈칸이 정상 생성되는지,
퀴즈 문서에 문항 수만큼 답 칸이 있고 정답이 빠짐없이 들어갔는지, 발송 일정이 "3일 학습 → 다음 날 퀴즈"로 도는지.
